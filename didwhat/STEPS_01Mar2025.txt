2. There are packages that fail to build because of unsupported spec file macros in Azure Linux.  These packages are:
cjkuni-uming-fonts
delve
google-noto-sans-cjk-vf-fonts

python-tox

We add all these except for google-carlito-fonts, to the pkglist_override_build_by_rem.
The reason to not add google-carlito-fonts to the remove list is that it does not
occur in the generated list in first place.  There is not need to remove it.
3. The reason for having perl-Test2-Suite and setup in the remove list are no
   more valid now.  But we will just keep these.  Since these are not there in 
   wkg_pkgs_to_build, their existence in the remove list is meaningles.

KNOWN ISSUES: TO BE FIXED AFTER SPECS-EXTENDED MANIPULATION
-----------------------------------------------------------
From the previous notes, we know that there still are problems to be faced.
But first we will use this generated lists to manipulate the SPECS-EXTENDED folder 
and then tackle the build failures.
These build failures will be:
1. Parse failure of ibus.spec.  The fix to this will be to use the ibus.spec from the previous build attempt.  It is nothing but 
   Azure Linux ibus.spec modified for the Version and Release (release is made 1).
2. There will be failure in addition of minizip-ng reported by grapher.  The fix is to give up on using the new name minizip-ng
   for the time being.  Therefore, the folder minizip will be restored and the folder minizip-ng will be removed.
3. Continuing from the above the package name in the build list will be changed to minizip from minizip-ng.  This we may do by 
   manually editing the wkg_pkgs_to_build or starting to use patched1_wkg_pkgs_to_build. 
4. There will be a failure to add pcp package too.  Again grapher will be the tool which reports this failure.
5. As noted in the earlier notes, this time we will do the same.  That, is comment out the BuildRequires on 
   ibus-table-chinese-* packages and thereby break the circular dependency.
6. A build will then report that the srpmpacker tool has skipped several packages because those can't be built on current architecture.
   Fix these by removing the ExclusiveArch tag from their spec files.
